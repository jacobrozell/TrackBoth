## 0. How to use this document (read first)

You are rebuilding TrackBoth into a focused, production-quality iOS app that helps people **break an addiction or compulsive habit** (a "vice") while **building the habits that replace it**. This doc has everything you need: the reasoning, the target product, exact rules and algorithms, a file-by-file keep/cut list, and the phases in order.

### 0.1 Operating rules (do not break these)

1. **Work the phases in order** (§10). Don't start a phase until the one before it passes its Definition of Done (DoD).
2. **Each phase ends green.** The project builds, unit tests pass, and you've made one commit for the phase. Inside a phase, commit as often as you like, but **only push commits that build**.
3. **Never hand-edit `TrackBoth/TrackBoth.xcodeproj`.** The project is generated by XcodeGen from `TrackBoth/project.yml`. After adding, moving, or deleting any file, run `xcodegen generate` in `TrackBoth/` and commit the regenerated `.xcodeproj` along with your change. (`REFACTOR_IMPLEMENTATION.md` says files must be added in Xcode. That's wrong for this repo: `project.yml` lists folders, so XcodeGen picks up new files on its own.)
4. **`Domain/` is pure Swift.** Files there import `Foundation` only: no `SwiftUI`, no `SwiftData`, no `UIKit`. Every function takes `now: Date` and `calendar: Calendar` as parameters (with defaults) so tests can control time.
5. **Reads in views, writes in the store.** Views may use `@Query` to read models. Every write (insert, update, delete, save) goes through `RecoveryStore` (§6.4). No `modelContext.insert` or `modelContext.delete` in a View or ViewModel.
6. **No new dependencies.** No SwiftPM packages, no analytics SDKs, no network calls. Everything stays on the device.
7. **All user-facing copy lives in `Domain/Copy/RecoveryCopy.swift`** (or a `Copy` enum next to the feature) and follows the language rules in §4.6. No guilt, no shame, no red "X".
8. **Accessibility ships with the feature, not after it:** VoiceOver labels, Dynamic Type up to AX5, 44×44pt tap targets, Reduce Motion, and WCAG AA contrast (§8.6).
9. **Stop and ask the owner** (batch your questions, don't trickle them) only for: a scope change beyond this doc, anything destructive to real user data, spending money or adding credentials, or a fork this doc doesn't settle. For anything else, pick the sensible default, write it down in the Progress Log (§14), and keep going.
10. **Update docs as you go.** Each phase lists the docs it touches. A fresh session should be able to resume from the Progress Log alone.

## 1. Where the app is today (audit, 2026-10-28)

### 1.1 Facts

| Area | Current state |
|------|---------------|
| Stage | Never shipped. Build 5 archived 2026-06-22, never uploaded to TestFlight. **No App Store users, so no shipped data to migrate.** |
| Size | ~21.7k lines of Swift across ~200 files, plus a widget extension (8 widget configurations) and an archived Watch app. |
| Stack | SwiftUI + SwiftData (iOS 18+), XcodeGen, Swift Charts, `@Observable` view models. |

| Notifications | None (spec'd for "1.2"). |
| Privacy | No app lock, no privacy screen in the app switcher, **no `PrivacyInfo.xcprivacy`** (required by App Store Connect, because the app uses `UserDefaults`). |
| Widget | Code exists, but it isn't embedded in the app, and the App Group entitlements are empty, so it couldn't work anyway. |
| Docs | Specs live in `Specs/` but docs link to `specs/` (breaks on case-sensitive filesystems). Many specs are stale or contradict each other. `project.yml` says build 4, status docs say build 5. |
| Tests | ~40 unit test files (domain, view models, export), 16 UI tests. CI builds and runs unit tests with a 50% core-file coverage gate. |

### 1.2 Diagnosis

The engineering is solid, but the **product has no center**. It's a general habit tracker with charts, goals, quantities, moods, themes and widgets, and the vice features are bolted on. For someone fighting an addiction, it fails at the moments that matter:

1. **When an urge hits**, there's nothing to open. The "Motivation" tab is a list, not a tool for getting through the next ten minutes.
2. **After a slip**, the app punishes you: the streak resets to 0, savings reset to $0, a red ✕ appears, and milestones never come back. This feeds the **abstinence violation effect** (§2.2), the "I already blew it, so what the hell" spiral that turns one lapse into a full relapse.
3. **Forgetting to log is treated like failing.** That trains people to quit the app, not the vice.
4. **Nothing brings you back.** There are no reminders, so the daily loop depends on memory alone.
5. **Too many surfaces** (5 tabs, 4 layouts each, goals, charts, quantities, themes) mean nothing is excellent and QA never finishes.

The overhaul fixes this by **cutting about 60% of the surface** and rebuilding around one loop.

## 2. Product thesis and psychology

### 2.1 One-sentence product

> **TrackBoth helps you quit what's hurting you and build what helps: a 10-second daily check-in, a tool for riding out urges, and progress a slip can't erase.**

Positioning: *"Quit vices. Build habits."* The "Both" in the name now means **quit one thing and build its replacement**. That's grounded in habit-reversal research: a behavior you remove leaves a gap, and a competing behavior should fill it.

### 2.2 The psychology the design is built on

Every feature below traces back to one of these. If a feature can't be traced, it gets cut.

| Principle | Source (for the specs) | What it means for TrackBoth |
|-----------|-----------------------|-----------------------------|
| **Abstinence violation effect (AVE)** | Marlatt & Gordon, *Relapse Prevention* (1985) | After a lapse, people who blame themselves and feel all-or-nothing are much more likely to fully relapse. **So:** a slip restarts the current run but never erases total free days, savings, or "27 of the last 30 days". Slip copy is compassionate and frames the slip as information. |
| **Urge surfing** | Bowen, Chawla & Marlatt, *Mindfulness-Based Relapse Prevention* (2010) | Urges rise, peak and pass like a wave. Watching them instead of obeying them weakens them. **So:** the core in-the-moment feature is a guided "ride it out" screen with breathing, a timer, your reasons, and your plan. |
| **Implementation intentions** | Gollwitzer (1999) | "If X happens, then I will Y" plans roughly double follow-through. **So:** every vice has one optional "When I feel the urge, I will…" plan, shown during urges and edited after slips. |
| **Motivational interviewing / personal values** | Miller & Rollnick | Reasons you put in your own words beat generic motivation. **So:** onboarding asks *why* and saves the answer as the first Reason. Reasons come up during urges and after slips. |
| **Trigger awareness (HALT and friends)** | Recovery practice (Hungry, Angry, Lonely, Tired) | Seeing your own patterns builds self-efficacy. **So:** slips and urges get optional one-tap trigger tags. Progress shows your top triggers and your hardest time of day. |
| **Fogg Behavior Model: B = MAP** | BJ Fogg, *Tiny Habits* | Behavior needs Motivation + Ability + a Prompt. **So:** a daily prompt (one notification), maximum ability (the check-in takes about 10 seconds), and an immediate celebration (haptic + animation). |
| **Missing one day doesn't break a habit** | Lally et al. (2010), *How are habits formed* | One missed day didn't measurably hurt habit formation. **So:** habit streaks follow "never miss twice": one missed day pauses the streak, two in a row end it. |
| **Self-compassion predicts recovery better than self-criticism** | Neff; addiction research on shame | **So:** no red, no ✕, no "failed". Slips use amber and calm wording. |
| **Language matters** | NIDA, *Words Matter* | "Clean/dirty" stigmatizes. **So:** use "free" ("12 days free"), "slip" (not "relapse" or "fail"), and "use" (not "abuse"). |

### 2.3 The core loop

```
          ┌────────────────────────────────────────────────────────────┐
          │                                                            │
   PROMPT │  Daily reminder at your chosen time (one per day, max)     │
          │  + an urge (internal) → home-screen quick action "Urge"    │
          ▼                                                            │
   ACTION │  Check-in: "Free today?" per vice + tick helper habits      │
          │  (≤10 seconds)   ─or─   Urge flow: ride it out (2–10 min)   │
          ▼                                                            │
   REWARD │  Immediate: haptic + "13 days free · $104 saved"            │
          │  Milestones: 1, 3, 7, 14, 30… days (re-earnable after slip) │
          │  Urges beaten counter: "That's 6 urges you've ridden out"  │
          ▼                                                            │
   INVEST │  Reasons, your if-then plan, trigger tags, helper habits →  │
          │  makes the next urge flow more personal and more effective │
          └──────────────────────────────── (next day) ─────────────────┘
```

**Ethical guardrail:** success means the user needs the app *less* over time. We don't optimize for time-in-app. No variable-reward slot mechanics, no streak freezes you pay for, no guilt notifications, at most one reminder a day plus milestone notices, no leaderboards, no social comparison.

### 2.4 What we are deliberately NOT building

| Cut | Why |
|-----|-----|
| Goals (weekly/monthly/yearly targets, quantity goals, Goals tab) | A monthly vice target ("8 times this month") contradicts quitting. Milestones are the goal. |
| Quantity, units, mood chips, starred entries | Extra input on every log adds friction and doesn't change behavior. Trigger tags replace mood where it matters (slips and urges). |
| Charts tab (line, bar, heatmap), chart PNG/PDF export | Generic analytics. Replaced by a calendar plus three recovery stats. |
| Multiple color themes, font picker | Decoration. One calm palette that follows system light/dark. |
| Per-device layout files (4 per screen) | 4× the QA work. **1.0 ships iPhone portrait.** iPad and landscape come back in Phase 15 as **one adaptive layout per screen**, not separate files (D6, §8.7). |
| Widget, Watch, Live Activities, Shortcuts | Post-launch. A single "days free" widget is Phase 14 (optional). |
| Launch splash animation | Delays the moment of need. The system launch screen is enough. |
| Week-start picker | Use `Calendar.current.firstWeekday` (follows the user's locale). |
| Placeholder "My habit / My vice" rows | Fake data. Onboarding requires one real choice. |
| Demo data in Release | Debug and screenshots only. |

## 4. Target product

### 4.1 Information architecture

Three tabs. That's it.

| Tab | SF Symbol | Purpose |
|-----|-----------|---------|
| **Today** | `sun.max` | Check-in, vice cards with live free-time, helper habit checklist, the **"I'm having an urge"** button. |
| **Progress** | `chart.line.uptrend.xyaxis` | One card per metric with its key numbers → tap for Metric Detail (calendar, reasons, plan, triggers, history editing). |
| **Settings** | `gearshape` | Reminders, app lock, appearance, backup/restore, delete, get help now, about. |

Presented flows (sheets or full-screen covers): **Check-in**, **Urge**, **Slip**, **Celebration**, **Add/Edit metric**, **Day editor**, **Onboarding**, **Lock screen**.

Entry points into the **Urge** flow: the Today button, the home-screen quick action (long-press the app icon), the `trackboth://urge` URL, and the "Having an urge?" link in the Check-in sheet.

### 4.2 Today screen

```
┌──────────────────────────────────────┐
│ Today                    Tue, Oct 28 │  large title + date
│                                      │
│ ┌──────────────────────────────────┐ │
│ │ ◉  Daily check-in             ›  │ │  CheckInBanner — only while today
│ │    3 to go · about 10 seconds    │ │  isn't fully checked in
│ └──────────────────────────────────┘ │
│                                      │
│ QUITTING                             │  section header
│ ┌──────────────────────────────────┐ │
│ │ [wineglass]  Alcohol             │ │  ViceCard
│ │ 12 days free                     │ │  big rounded number
│ │ 12d 4h 13m  ·  $96 saved         │ │  live (TimelineView, minute)
│ │ ● ● ● ○ ● ● ◐   last 7 days      │ │  ●confirmed ○presumed ◐today ▲slip
│ │ Next milestone: 14 days (2 days) │ │
│ └──────────────────────────────────┘ │
│                                      │
│ BUILDING                             │
│ ┌──────────────────────────────────┐ │
│ │ ○  Go for a walk       5-day run │ │  HabitCheckRow (tap circle = done)
│ │ ●  Call a friend       2-day run │ │
│ │ ○  Drink water   Don't miss twice│ │  at-risk hint (amber, gentle)
│ └──────────────────────────────────┘ │
│                                      │
│ ┌──────────────────────────────────┐ │
│ │      [wind]  I'm having an urge  │ │  SOSButton — pinned above tab bar
│ └──────────────────────────────────┘ │
├──────────────────────────────────────┤
│   Today      Progress      Settings  │
└──────────────────────────────────────┘
```

Rules:
- Order: CheckInBanner (if pending) → "Quitting" (vices, by `sortOrder`) → "Building" (habits) → SOSButton pinned with `safeAreaInset(edge: .bottom)`.
- The SOSButton shows only if there's at least one active vice.
- Tapping a ViceCard opens Metric Detail (pushes onto the Progress tab's stack: switch tab, then push. Or present Metric Detail as a sheet from Today, which is simpler; **use the sheet**).
- Tapping a habit's circle toggles done for today (haptic `.success` on done, `.selection` on undo). Tapping the row text opens Metric Detail.
- Empty state (no metrics; only reachable after deleting everything): "Start with one thing" + button → Add metric.
- If yesterday is unconfirmed for any vice **and** the user opened the app before noon, show one dismissible row above the banner: "Yesterday: were you free from Alcohol?" with [Yes] [I slipped]. (Keeps the calendar honest without nagging.)

### 4.3 Daily check-in (the core ritual)

Sheet, `.presentationDetents([.medium, .large])`.

```
Daily check-in · Tue, Oct 28

Alcohol
 [  Free today  ]   [ I slipped ]

Social media
 [  Free today  ]   [ I slipped ]

Building
 ○ Go for a walk
 ○ Call a friend

Having an urge right now? →            (opens Urge flow)

[ Done ]                                 (enabled once every vice has an answer)
```

- "Free today" → `RecoveryStore.markFree(metric, on: today)`.
- "I slipped" → present the **Slip flow** with `day = today`. When it finishes, that row shows "Slip logged · thanks for being honest" and can't be toggled back from here (fix it in the Day editor).
- Habit rows toggle done.
- **Done** → `CheckInCompleteView` (inside the same sheet): an animated check, then one line per vice ("13 days free · $104 saved"), then any milestone → Celebration.
- Check-in counts as **complete** for a day when every active vice has an entry for that day. Habits are optional for completeness.

### 4.4 Urge flow ("I'm having an urge")

`fullScreenCover`, calm background. Four steps:

1. **Which one?** Skipped when there's only one active vice. A list of active vices.
2. **How strong?** Five big buttons (1 Mild … 5 Intense), default 3, with a "Skip" option. Creates an `UrgeEvent(outcome: .inProgress)`.
3. **Ride it out**
   - A `BreathingCircle`: grows for 4s ("Breathe in"), shrinks for 6s ("Breathe out"), loops. Under Reduce Motion it shows only the text cue, switching every 4s/6s.
   - Countdown starting at **5:00**, with a "+5 min" button. Copy above it: *"Urges rise, peak, and pass, like a wave. Let's ride this one out."*
   - **Your why** card: rotates through the vice's Reasons every 8s (or shows them as a list under Reduce Motion).
   - **Your plan** card, if `ifThenPlan` is set: "When I feel the urge, I will: …"
   - **Try one instead:** chips for active habits. Tapping one marks it done today (checkmark plus haptic).
   - Buttons: **[The urge passed]** (primary) and **[I slipped]** (secondary, plain text style). The X in the corner asks "How did it go?" → passed / slipped / not sure.
   - When the timer hits 0: a soft haptic and "Still with it? You can add 5 minutes, or check in with yourself."
4. **Outcome**
   - *Passed* → `outcome = .resisted` → screen: "You rode it out." + "That's **N** urges you've beaten." + optional "What set it off?" trigger chips → **Done**.
   - *Slipped* → `outcome = .slipped` → Slip flow, prefilled with the triggers picked here. The urge's triggers are copied onto the slip entry.
   - *Not sure* → `outcome = .unknown`, back to Today.

### 4.5 Slip flow

Sheet, one scrolling form, **no red anywhere**.

```
Thanks for being honest.
A slip is information, not failure. Let's learn from it.

When?   [Just now] [Earlier today] [Yesterday] [Pick a day…]
What was going on?  (chips, multi-select — TriggerTag list §6.7)
Anything else? (optional note)
Next time I feel the urge, I will…  (prefilled with current plan)

[ Save ]
```

`occurredAt` rules: *Just now* and *Earlier today* = `now`. *Yesterday* = start of today − 1 second (23:59:59 yesterday). *Pick a day* = that day at 23:59:59, or `now` if it's today. The date picker range is from `startOfDay(metric.startedAt)` to today.

On save: `RecoveryStore.logSlip(...)`, and if the plan text changed, update `metric.ifThenPlan`. Then show **SlipSummaryView**:

> **Your free clock restarts from here.**
> You still have **27 of your last 30 days** free and **$135** saved. That progress is real and it stays.
> *[Reason card: first Reason]*
> Need more support? → Get help now (Crisis resources, §4.9)
> **[Back to Today]**

Haptic: `.impact(weight: .light)`. Never `.error`.

### 4.6 Language rules (applies to all copy)

| Use | Don't use |
|-----|-----------|
| free, free from, days free | clean, sober (unless the user typed it), dirty |
| slip, slipped | relapse, fail, failed, broke, ruined, lost |
| urge | craving is OK; temptation is moralizing |
| "Thanks for being honest" | "Oops", "Too bad", "Try harder" |
| "Your clock restarts" | "Your streak was reset to 0" |
| "Don't miss twice" (habits) | "You'll lose your streak!" |
| Second person, short sentences, plain words | Clinical jargon, exclamation-mark spam (max one per screen) |

Notification copy is never guilt-based. In **discreet mode** it never names the vice.

### 4.7 Progress tab

- Top: a summary row of three `StatTile`s: **Total saved** (sum across vices, hidden if no costs set), **Urges beaten** (all time), **Days checked in** (last 30).
- Then one `ProgressMetricCard` per active metric (vices first). For a vice: "12 days free · longest 40 · 27/30 days". For a habit: "5-day run · best 14 · 22/30 days". A chevron leads to **Metric Detail**.
- An "Archived" disclosure at the bottom lists archived metrics (they can be restored).

**Metric Detail** (`MetricDetailScreen`), top to bottom:
1. Header: icon, name, live free clock (vice) or run count (habit).
2. `StatTile` grid (2×2). Vice: Current run, Longest run, Free days (last 30), Saved. Habit: Current run, Best run, Done (last 30), Done (all time).
3. **Calendar:** month grid with month paging back to `startedAt`. Day cell states: confirmed free (solid brand), presumed free (outlined brand), slip (amber dot), habit done (solid indigo), before start or future (dimmed). Tap a past day → **Day editor** sheet: vice = [Free] [Slipped] [Clear]; habit = [Done] [Not done]. Changing to "Slipped" opens the Slip flow for that day.
4. **Your reasons:** a list with add, edit, swipe-to-delete, and drag to reorder. The first one is the "primary" reason.
5. **Your plan:** the if-then text with an Edit button.
6. **Patterns** (vices only, shown once there are ≥3 slips + urges combined): top 3 triggers as horizontal bars with counts; "Hardest time: Evenings" (§6.8).
7. **Urges:** "Beaten 9 of 11" (resisted / total, excluding in-progress).
8. Toolbar → **Edit** (MetricForm: name, icon, start date, cost per day, archive, delete).

## 6. Data model and rules

### 6.1 Conventions

- **Day anchor:** store calendar days as **local noon** (`DayMath.anchor(_:)`). Compare days with `calendar.startOfDay(for:)`. *Why noon:* storing midnight means a westward time-zone change shifts the value into the previous day (00:00 EDT = 21:00 PDT the day before). Noon survives time-zone shifts of up to ±11 hours.
- **Timestamps** (`occurredAt`, `startedAt`, urge times) are real `Date`s, not anchors.
- **Enums are stored as raw `String`s** (`statusRaw`, `outcomeRaw`) with computed accessors. SwiftData `#Predicate` can't filter on enum properties reliably. Raw strings also keep a future CloudKit move possible.
- Every stored property **has a default value** and every relationship-like reference is a `UUID` (same pattern as the current code). That keeps future iCloud sync possible (CloudKit requires defaults/optionals).
- Lists of tags are stored as a single `|`-joined string (`triggersRaw`) with a typed accessor. Don't use `[String]` attributes.
- **One entry per (metric, day).** `RecoveryStore` upserts it. Never insert a second entry for the same day.

Rules:
- Every public method ends with `context.saveChanges(operation:entity:)`. If that returns `false`, throw `RecoveryStoreError.saveFailed`.
- After every successful save, post `Notification.Name.recoveryDataChanged`. `RootView` listens and refreshes scheduled notifications (§7.5).
- `entry(for:on:)` is internal: it fetches with `FetchDescriptor<MetricEntry>` using `#Predicate { $0.metricID == id && $0.day >= start && $0.day < end }`, where `start`/`end` bracket the calendar day.
- `logSlip` refuses (throws `.slipBeforeStart`) when `occurredAt < startOfDay(metric.startedAt)`.
- `markFree` on a day that's already `.slipped` → **do nothing**. Only the Day editor's explicit "Free" (which calls `clearDay` and then `markFree`) can override a slip.

### 6.5 `DayMath` (`Domain/Calendar/DayMath.swift`)

```swift
import Foundation

enum DayMath {
    /// Local-noon anchor used for stored `MetricEntry.day` values.
    static func anchor(_ date: Date, calendar: Calendar = .current) -> Date {
        calendar.date(bySettingHour: 12, minute: 0, second: 0, of: date) ?? calendar.startOfDay(for: date)
    }

    static func key(_ date: Date, calendar: Calendar = .current) -> Date {
        calendar.startOfDay(for: date)
    }

    /// 23:59:59 on the given day (used when a slip is logged for a past day).
    static func endOfDay(_ date: Date, calendar: Calendar = .current) -> Date {
        let start = calendar.startOfDay(for: date)
        return calendar.date(byAdding: DateComponents(day: 1, second: -1), to: start) ?? date
    }

    /// Every day key from `start` through `end`, inclusive.
    static func days(from start: Date, through end: Date, calendar: Calendar = .current) -> [Date] {
        var result: [Date] = []
        var cursor = calendar.startOfDay(for: start)
        let last = calendar.startOfDay(for: end)
        while cursor <= last {
            result.append(cursor)
            guard let next = calendar.date(byAdding: .day, value: 1, to: cursor) else { break }
            cursor = next
        }
        return result
    }
}
```

### 6.6 Recovery math (`Domain/Recovery/RecoveryMath.swift`, `Domain/Habits/HabitMath.swift`)

Domain works on value types, never on `@Model` objects. `Data/Snapshots.swift` maps models to these.

```swift
import Foundation

struct ViceHistory: Equatable {
    var startedAt: Date
    var slips: [Date]                 // occurredAt of every .slipped entry
    var confirmedFreeDays: Set<Date>  // startOfDay keys of .free entries
}

enum DayState: Equatable {
    case beforeStart, future, slipped, confirmedFree, presumedFree, todayPending
}

enum RecoveryMath {
    static func relevantSlips(_ h: ViceHistory) -> [Date] {
        h.slips.filter { $0 >= h.startedAt }.sorted()
    }

    /// When the current free run began: the latest slip, or the quit date.
    static func currentRunStart(_ h: ViceHistory) -> Date {
        relevantSlips(h).last ?? h.startedAt
    }

    /// Whole 24-hour periods in the current run. Drives "N days free" and milestones.
    static func currentRunDays(_ h: ViceHistory, now: Date, calendar: Calendar = .current) -> Int {
        let start = currentRunStart(h)
        guard now > start else { return 0 }
        return calendar.dateComponents([.day], from: start, to: now).day ?? 0
    }

    /// Day/hour/minute components for the live clock.
    static func currentRunClock(_ h: ViceHistory, now: Date, calendar: Calendar = .current) -> DateComponents {
        let start = currentRunStart(h)
        return calendar.dateComponents([.day, .hour, .minute], from: start, to: max(now, start))
    }

    static func longestRunDays(_ h: ViceHistory, now: Date, calendar: Calendar = .current) -> Int {
        let points = [h.startedAt] + relevantSlips(h) + [max(now, h.startedAt)]
        return zip(points, points.dropFirst())
            .map { calendar.dateComponents([.day], from: $0, to: $1).day ?? 0 }
            .max() ?? 0
    }

    static func state(of day: Date, in h: ViceHistory, now: Date, calendar: Calendar = .current) -> DayState {
        state(of: calendar.startOfDay(for: day), in: h, slipDays: slipDays(h, calendar), now: now, calendar: calendar)
    }

    /// (free, counted) over the last `window` days ending today.
    static func freeDays(inLast window: Int, _ h: ViceHistory, now: Date, calendar: Calendar = .current) -> (free: Int, counted: Int) {
        let today = calendar.startOfDay(for: now)
        guard window > 0, let first = calendar.date(byAdding: .day, value: -(window - 1), to: today) else { return (0, 0) }
        return tally(DayMath.days(from: first, through: today, calendar: calendar), h, now: now, calendar: calendar)
    }

    /// Free days since the quit date. Never reset by a slip.
    static func totalFreeDays(_ h: ViceHistory, now: Date, calendar: Calendar = .current) -> Int {
        tally(DayMath.days(from: h.startedAt, through: now, calendar: calendar), h, now: now, calendar: calendar).free
    }

    /// Money saved = total free days × cost per day. Not reset by a slip.
    static func moneySaved(totalFreeDays: Int, costPerDay: Decimal?) -> Decimal? {
        guard let costPerDay, costPerDay > 0, totalFreeDays > 0 else { return nil }
        return costPerDay * Decimal(totalFreeDays)
    }

    // MARK: - Private

    private static func slipDays(_ h: ViceHistory, _ calendar: Calendar) -> Set<Date> {
        Set(relevantSlips(h).map { calendar.startOfDay(for: $0) })
    }

    private static func state(of key: Date, in h: ViceHistory, slipDays: Set<Date>, now: Date, calendar: Calendar) -> DayState {
        let today = calendar.startOfDay(for: now)
        if key < calendar.startOfDay(for: h.startedAt) { return .beforeStart }
        if key > today { return .future }
        if slipDays.contains(key) { return .slipped }
        if h.confirmedFreeDays.contains(key) { return .confirmedFree }
        return key == today ? .todayPending : .presumedFree
    }

    private static func tally(_ days: [Date], _ h: ViceHistory, now: Date, calendar: Calendar) -> (free: Int, counted: Int) {
        let slips = slipDays(h, calendar)
        return days.reduce(into: (free: 0, counted: 0)) { acc, day in
            switch state(of: day, in: h, slipDays: slips, now: now, calendar: calendar) {
            case .confirmedFree, .presumedFree:
                acc.free += 1
                acc.counted += 1
            case .slipped:
                acc.counted += 1
            case .beforeStart, .future, .todayPending:
                break
            }
        }
    }
}
```

```swift
struct HabitHistory: Equatable {
    var startedAt: Date
    var doneDays: Set<Date>   // startOfDay keys of .done entries
}

enum HabitMath {
    /// "Never miss twice": one missed day pauses the run; two missed days in a row end it.
    /// Today never counts as a miss because the day isn't over.
    static func currentRun(_ h: HabitHistory, now: Date, calendar: Calendar = .current) -> Int {
        let firstDay = calendar.startOfDay(for: h.startedAt)
        var cursor = calendar.startOfDay(for: now)
        let today = cursor
        var run = 0
        var consecutiveMisses = 0
        while cursor >= firstDay {
            if h.doneDays.contains(cursor) {
                run += 1
                consecutiveMisses = 0
            } else if cursor != today {
                consecutiveMisses += 1
                if consecutiveMisses >= 2 { break }
            }
            guard let previous = calendar.date(byAdding: .day, value: -1, to: cursor) else { break }
            cursor = previous
        }
        return run
    }

    /// Yesterday was missed and today isn't done yet. Show the gentle "Don't miss twice" hint.
    static func isAtRisk(_ h: HabitHistory, now: Date, calendar: Calendar = .current) -> Bool {
        let today = calendar.startOfDay(for: now)
        guard let yesterday = calendar.date(byAdding: .day, value: -1, to: today),
              yesterday >= calendar.startOfDay(for: h.startedAt) else { return false }
        return !h.doneDays.contains(today)
            && !h.doneDays.contains(yesterday)
            && currentRun(h, now: now, calendar: calendar) > 0
    }

    /// Longest run ever, using the same never-miss-twice rule walking forward.
    static func bestRun(_ h: HabitHistory, now: Date, calendar: Calendar = .current) -> Int {
        let today = calendar.startOfDay(for: now)
        var best = 0
        var run = 0
        var consecutiveMisses = 0
        for day in DayMath.days(from: h.startedAt, through: now, calendar: calendar) {
            if h.doneDays.contains(day) {
                run += 1
                consecutiveMisses = 0
            } else if day != today {
                consecutiveMisses += 1
                if consecutiveMisses >= 2 { run = 0 }
            }
            best = max(best, run)
        }
        return best
    }

    static func doneCount(inLast window: Int, _ h: HabitHistory, now: Date, calendar: Calendar = .current) -> Int {
        let today = calendar.startOfDay(for: now)
        guard window > 0, let first = calendar.date(byAdding: .day, value: -(window - 1), to: today) else { return 0 }
        return h.doneDays.filter { $0 >= first && $0 <= today }.count
    }
}
```

### 6.9 Milestones (`Domain/Milestones/MilestonePolicy.swift` + `Services/MilestoneLedger.swift`)

```swift
enum MilestonePolicy {
    static let viceDays = [1, 3, 7, 14, 30, 60, 90, 180, 270, 365]
    static let habitRuns = [3, 7, 14, 30, 60, 100, 200, 365]

    /// Every threshold reached by `value`, including yearly ones after 365 (730, 1095, …).
    static func reached(_ value: Int, isVice: Bool) -> [Int] {
        let base = (isVice ? viceDays : habitRuns).filter { $0 <= value }
        let yearly = value >= 730 ? Array(stride(from: 730, through: value, by: 365)) : []
        return base + yearly
    }

    static func next(after value: Int, isVice: Bool) -> Int {
        let list = isVice ? viceDays : habitRuns
        return list.first { $0 > value } ?? ((value / 365) + 1) * 365
    }

    /// Celebrate only the HIGHEST newly reached threshold (no stacked celebrations after backfills).
    static func pending(value: Int, isVice: Bool, highestCelebrated: Int) -> Int? {
        let effectiveHighest = value < highestCelebrated ? 0 : highestCelebrated   // run restarted → re-earnable
        guard let top = reached(value, isVice: isVice).last, top > effectiveHighest else { return nil }
        return top
    }
}
```

> Domain never sees `HabitType` (that enum lives in `Data/Models/` beside the SwiftData models). Callers pass `metric.habitType == .vice`.

`MilestoneLedger` (UserDefaults, key `milestoneLedger.v2`, `[metricUUIDString: Int]`):
- `highestCelebrated(for:) -> Int`
- `record(_ threshold: Int, for:)`
- `reset(for:)` when the value has dropped below the stored highest (call before evaluating pending).
- `clearAll()`

When to check: on Today `onAppear`, after the check-in Done, after an urge resolves, and when the app becomes active. If something's pending → present `CelebrationView`. If several metrics have pending milestones, show them one after another, vices first.

### 7.6 App lock (`Services/AppLock.swift`)

```swift
import LocalAuthentication
import Observation

@Observable @MainActor
final class AppLock {
    static let shared = AppLock()
    var isLocked: Bool
    var isEnabled: Bool {
        didSet { Preferences.appLockEnabled = isEnabled }
    }

    private init() {
        isEnabled = Preferences.appLockEnabled
        isLocked = Preferences.appLockEnabled
    }

    var isAvailable: Bool {
        LAContext().canEvaluatePolicy(.deviceOwnerAuthentication, error: nil)
    }

    func lockIfEnabled() { if isEnabled { isLocked = true } }

    func unlock() async {
        let context = LAContext()
        guard context.canEvaluatePolicy(.deviceOwnerAuthentication, error: nil) else {
            isLocked = false          // no passcode on device → can't lock; fail open, show a note in Settings
            return
        }
        do {
            if try await context.evaluatePolicy(.deviceOwnerAuthentication,
                                                localizedReason: "Unlock TrackBoth") {
                isLocked = false
            }
        } catch {
            // stay locked; LockScreen shows "Unlock" button again
        }
    }
}
```

### 8.7 Adaptive-ready rules (D6: iPad + landscape in a future release)

1.0 ships iPhone portrait only. Build every screen so that turning on iPad and landscape (Phase 15) means **adding** layouts, not rewriting screens:

1. **No device checks.** Never use `UIDevice.current.userInterfaceIdiom`, screen-size constants, or `UIScreen.main.bounds`. Use `@Environment(\.horizontalSizeClass)` / `verticalSizeClass` and the size the view is given.
2. **One readable column.** Wrap each screen's scroll content in `ReadableColumn` (a DesignSystem component: `frame(maxWidth: 640)` centered, with `Spacing.l` side padding). On iPhone portrait it's full width. On iPad it stays readable.
3. **No fixed widths or heights** on cards, grids, or the calendar. Use flexible frames, `GridItem(.adaptive(minimum:))`, and `ViewThatFits`.
4. **Navigation that can split.** Progress → Metric Detail uses `NavigationStack` with value-based `navigationDestination(for: UUID.self)`, so Phase 15 can swap it for `NavigationSplitView` on regular width without touching the detail screen.
5. **Full-screen flows** (Urge, Onboarding, Lock) center their content in a `ReadableColumn` and never assume portrait height. Put the breathing circle and the buttons in a `ViewThatFits(in: .vertical)` that falls back to a horizontal arrangement when height is short.
6. **Previews:** every screen gets one extra landscape preview (`#Preview(traits: .landscapeLeft)`). It doesn't have to look final, but nothing may clip or overlap. That keeps Phase 15 small.

## 13. Appendix

### 13.1 Glossary
- **Vice / Quitting:** something the user wants to stop. Shows "days free".
- **Habit / Building:** a helper behavior the user wants to do daily. Shows "N-day run".
- **Run:** the current unbroken stretch (vices: since the last slip; habits: never-miss-twice).
- **Presumed free:** a past day with no entry after the quit date. It counts as free but shows hollow.
- **Check-in:** confirming today for every active vice (habits optional).

### 13.5 Known pitfalls for the implementing agent
1. **`@Query` with dynamic predicates:** build the `Query` in `init` (see the old `MetricMotivationDetailView` pattern). You can't change it after init. Pass IDs as local `let`s captured by the `#Predicate`.
2. **`#Predicate` and enums:** use the raw string properties (`statusRaw == "slipped"`), never `status == .slipped`.
3. **Sheets inside sheets:** SwiftUI allows only one presented sheet per view. Present the Slip flow *from inside* `CheckInSheet` with its own `.sheet` modifier, not from `RootView`.
4. **`TimelineView` + heavy computation:** compute stats outside the `TimelineView` closure. Only the clock string goes inside.
5. **Notification permission:** never request it at launch. Requesting it at the wrong moment gets a permanent "no".
6. **`Calendar.current` in tests:** banned. Inject `Calendar.testNY`.
7. **XcodeGen:** after *any* file add/move/delete, run `xcodegen generate` and commit the `.xcodeproj` changes, or CI will build a stale project.
8. **Don't silently "fix" the rules.** If a Domain rule feels wrong while you build the UI, stop, write it in the Progress Log, and ask. The rules in §6 are product decisions, not implementation details.
